# SEO Score – Free SEO Audit Tool

A Flask SEO audit tool that also runs as a **Cloudflare Python Worker (Free plan)**.
The UI, routes and audit columns are identical in both.

## Project structure

```
app.py                  Flask app – local development (uses `requests`)
src/
  worker.py             Cloudflare Worker entry point (routing + audit via Workers fetch)
  seo_core.py           HTML analysis shared by Flask and the Worker (standard library only)
  render.py             Tiny renderer for templates/index.html (replaces Jinja2 in the Worker)
  templates_bundle.py   GENERATED by the build – do not edit or commit
templates/              All pages (index.html = home); _header.html / _footer.html are shared partials (inlined by the build for the Worker)
static/                site.css + site.js (shared design system), logo, preview image
*.png, *.ico, robots.txt, sitemap.xml, llms.txt, site.webmanifest   static files
public/                 GENERATED static-assets folder served by Cloudflare – do not edit or commit
scripts/build.mjs       Generates src/templates_bundle.py and public/ (runs automatically on dev/deploy)
tests/                  test_seo_core.py, test_render.py (unit) and smoke.py (live Worker check)
wrangler.jsonc          Worker config            pyproject.toml / uv.lock   Worker Python config
requirements-local.txt  Flask dependencies for local use (NOT used for Cloudflare)
requirements-dev.txt    Optional: beautifulsoup4, for the parser parity test
package.json            Convenience scripts (npm test, npm run dev, ...)
```

Cloudflare does **not** use `requirements.txt` (pywrangler refuses to run if one exists). The Worker has no
third-party runtime dependencies: `src/` uses only the Python standard library plus Cloudflare's own `workers` SDK.

## Prerequisites

| Tool | Needed for | Install |
|---|---|---|
| Node.js 20+ (includes npm) | Wrangler, build script | https://nodejs.org or `winget install OpenJS.NodeJS.LTS` |

## Local development

### A. Flask version (quick, no Cloudflare)

```bash
python -m venv .venv
.venv/Scripts/activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements-local.txt
python app.py                     # http://localhost:10000
```

### B. The real Worker runtime (Pyodide inside workerd)

Linux / macOS / WSL:

```bash
npm install
uv run pywrangler dev             # http://localhost:8787
```

Native Windows – `pywrangler` cannot create its Pyodide environment there (`uv venv ... emscripten` fails), so use:

```bash
npm install
npm run dev:windows               # = uv pip install --target python_modules workers-runtime-sdk  +  wrangler dev
```

### Tests

```bash
npm test                          # same as: python -m unittest discover -s tests
pip install -r requirements-dev.txt   # optional: also compares the parser against BeautifulSoup
```

With the Worker running (`npm run dev` or `npm run dev:windows`), in another terminal:

```bash
npm run smoke                     # python tests/smoke.py http://127.0.0.1:8787
python tests/smoke.py https://your-domain.example      # same checks against a deployed Worker
```

The smoke test checks: home page, all page routes, static assets, 404, `POST /` for a normal site, a redirecting site,
an unresolvable domain, localhost/IP rejection, the per-audit domain limit, empty input, and the JSON view.

## Deploy to Cloudflare

### Linux / macOS / WSL

```bash
npx wrangler login
uv run pywrangler deploy
```

### Native Windows

```bash
npx wrangler login
npm run deploy:windows            # = uv pip install --target python_modules workers-runtime-sdk  +  wrangler deploy
```

(`uv run pywrangler deploy` fails on native Windows at the Pyodide-environment step.)

For CI/non-interactive use, skip `login` and set `CLOUDFLARE_API_TOKEN` (and `CLOUDFLARE_ACCOUNT_ID`).
No environment variables or secrets are required. The only setting is `MAX_DOMAINS` in `wrangler.jsonc`.

The first deploy publishes to `https://seo-audit-tool.<your-subdomain>.workers.dev`.
Open it and run `python tests/smoke.py https://seo-audit-tool.<your-subdomain>.workers.dev`.

### Custom domain

1. Add the domain to Cloudflare (Dashboard → **Add a domain**) and change the registrar's nameservers to the ones shown.
   Wait until the domain shows **Active**.
2. Dashboard → **Workers & Pages** → **seo-audit-tool** → **Settings** → **Domains & Routes** → **Add** → **Custom domain**.
3. Enter `www.freeseoaudit.site` → **Add domain**. Cloudflare creates the DNS record and certificate (usually under a minute).
   Repeat for the apex `freeseoaudit.site` if you want both.
4. Remove the old DNS record / hosting for that hostname first if one exists (a custom domain cannot replace an existing CNAME).

As code instead of dashboard – add to `wrangler.jsonc` and redeploy:
`"routes": [{ "pattern": "www.freeseoaudit.site", "custom_domain": true }]`

## How it works on Cloudflare

- Flask/WSGI is synchronous and cannot await the Workers `fetch`, so `src/worker.py` does the routing and calls
  `fetch` directly (redirects followed, 8 s page / 5 s robots.txt+sitemap.xml timeouts via `AbortSignal.timeout`).
- Static files are served by Cloudflare's assets layer from `public/` without invoking the Worker.
- `src/seo_core.py` replaces BeautifulSoup with a regex scan: ~5–10× less CPU, same results for title, meta description,
  word count, H1/H2, internal links (compared against BeautifulSoup on saved pages from Wikipedia, GitHub, BBC, NYTimes, Python.org, Cloudflare docs and others).
- Collected but not shown in the table (UI unchanged): final URL, redirected, response size in bytes, canonical, image count.
  See them with `curl -H "Accept: application/json" -d "domains=example.com" https://<your-site>/`.

## Known limitations (Cloudflare Free plan)

- **Up to 5 domains per audit** (`MAX_DOMAINS`). Free allows 50 subrequests per request and every redirect hop counts.
  Extra lines are shown in the table as `Skipped (max 5 per audit)`, not dropped silently.
- **10 ms CPU per request.** Waiting on other websites does not count, parsing does. Typical pages (<150 KB) take
  roughly 1–5 ms of CPU each in CPython, so an audit of several large sites in one request can exceed the limit
  (Cloudflare error 1102). HTML beyond the first 400,000 characters is not analysed. If this happens, audit fewer
  domains per request or use the Workers Paid plan (30 s CPU) and raise `MAX_DOMAINS`.
- Word count can differ by ~2% from the Flask version on pages with nested `<template>` elements.
- Public hostnames only: IP addresses, `localhost` and ports are rejected (Workers cannot reach them anyway).
- The Flask app (`app.py`) is unchanged in behaviour, including its original unlimited domains and `requests` timeouts;
  the JSON view and domain limit exist only in the Worker.
